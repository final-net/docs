## Idempotency

Send `Idempotency-Key: <uuid>` on each `POST` that you might retry. If you retry with the same key, Final returns the first response and does not run the request again.

- Final binds a key to its request body for 24 hours. If you send the same key with a different body, Final returns `409 idempotency_key_reused`.
- If you retry before the first request completes, Final returns `409 idempotency_in_flight`. Retry after Final returns a response to the first request.
- A replayed response contains `Idempotent-Replayed: true`.
- Final records every response that it returns, and 4xx responses also. Final replays each response unchanged.
- Retry with the same key only if you do not know whether the request completed. Examples are a timeout, a lost connection, or an app that the system suspended during the request.
- If Final returned a response and you want a new attempt, create a new key. The same key will replay the refusal.

This is most important for activation. Final creates the `client_secret` only once. If you lose the response, retry with the same key. This is the only way to recover the response.

## Rate limits

Each credential can send 200 requests per second. Above that limit, Final returns `429 rate_limited` with `Retry-After: 1`. Wait for that time, then send requests again.

Final counts proposals and activation against the publishable key. All installs of your app share this key. Final counts all requests after activation per connection.
