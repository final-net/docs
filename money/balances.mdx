Funds are in a root Balance. There is one root Balance for each approved asset.

A sub-balance sets limits on spend. It shares the funds of its root Balance. A card on a sub-balance spends the funds of the root Balance, within the limits of the sub-balance.

The full reference is [Balance](/reference/objects/balance).

On a sub-balance, `available`, `pending` and their `display_*` siblings are `null`.

The new `available` value can come a short time after a `deposit.credited` event. If you read the Balance when that event arrives, read it again. Do not assume that the value is current.

## List and read

- `GET /balances` lists the Balances that your grant can access.
- To list only the root Balances, add `?parent_balance_id=null`.
- To list the children of a parent, set `?parent_balance_id=` to the ID of the parent.
- To filter the list more, add `?asset=` or `?status=active|closed|all`.
- `GET /balances/{id}` returns one Balance.
- If the Balance is outside your grant, Final returns `404 not_found`. Final returns the same error for a Balance that does not exist.

## Create a sub-balance

Only an approval creates a root Balance. `POST /balances` creates a sub-balance below a root Balance, up to 7 levels deep:

```json
{
  "parent_balance_id": "balance_…",
  "label": "Groceries",
  "limits": [
    { "type": "rolling_window", "window": "P1D", "max": { "asset": "iso4217:USD", "amount": "50000" } }
  ],
  "parent_imposed_limits": [
    { "type": "lifetime", "max": { "asset": "iso4217:USD", "amount": "500000" } }
  ]
}
```

- `limits` contains the rules that the sub-balance applies to itself.
- `parent_imposed_limits` contains the rules that you set on it as the parent. A holder of only the sub-balance cannot change these rules.
- A sub-balance gets the asset of its root Balance. If you send `asset`, Final returns `400 parent_invalid`.

| Status | Code | Description |
| --- | --- | --- |
| 400 | `connection_root_not_allowed` | The request does not contain `parent_balance_id`. Only an approval creates a root Balance. |
| 400 | `parent_invalid` | The parent is unknown, outside your grant or closed, or the request contains `asset`. |
| 400 | `depth_exceeded` | The tree would be more than 7 levels deep below the root Balance. |
| 400 | `limit_invalid` | A rule has an incorrect format. |
| 403 | `user_action_required`, `verification_pending` | See [Gates](/money/gates). |

- `max.asset` is `iso4217:USD` or the asset of the Balance.
- A card swipe contains the amount in both denominations. Each rule uses the amount in its own denomination.
- The recipient of a card swipe is `{ "kind": "merchant", "id": <merchant_name> }`.

## Transactions

`GET /balances/{id}/transactions` lists the ledger, newest first. To filter the list, use `?type=`, `?from=` and `?to=`. Final returns the list in pages.

<TransactionShape />

The full reference is [Transaction](/reference/objects/transaction).

- A deposit credit contains `related.deposit_id`.
- A direct deposit also contains `related.deposit_receipt_id`, with one entry for each landing.
- A card spend does not contain a `related` block.
- If a card authorization reverses, the ledger shows a `card_auth` credit for the same amount.

`GET /transactions/export` returns the same history as a CSV file. This route works only in live mode.
