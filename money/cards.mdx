## Issue a card

`POST /cards` issues a card on a Balance. It is born `provisioning` and activates once the Balance's tree has a credited deposit: a card on a sub-balance activates on a credit anywhere in its root's tree.

```json
{
  "balance_id": "balance_…",
  "cardholder_info": {
    "name": "A. Nakamoto",
    "billing_address": {
      "line1": "1 Main St",
      "line2": null,
      "city": "Austin",
      "region": "TX",
      "postal_code": "78701",
      "country": "US"
    }
  }
}
```

`cardholder_info` is the name on the card and the billing address a merchant checks, for this card only. `line1`, `city`, `postal_code` and `country` are required, `region` is required for US and CA, and `country` is ISO 3166-1 alpha-2. A partial object, a name without an address or the reverse, is `400 invalid_request` naming the missing field in `param`.

Omitting `cardholder_info` issues the card in the user's verified name and address. If Final has no address on file for them, the call answers `403 user_action_required` with a URL; see [Gates](/money/gates). Sending `cardholder_info` skips that step.

The response is `{ "card": Card }` with `201`. One card per Balance: if one already exists you get it back with `200`.

| Status | Code | Meaning |
| --- | --- | --- |
| 400 | `balance_id_required` | No `balance_id`. |
| 403 | `user_action_required`, `verification_pending` | See [Gates](/money/gates). |
| 404 | `not_found` | The Balance is outside your grant. |
| 409 | `balance_closed` | The Balance is closed. |

## The Card object

```json
{
  "id": "card_…",
  "balance_id": "balance_…",
  "status": "provisioning",
  "network": null,
  "last4": null,
  "exp_month": null,
  "exp_year": null,
  "cardholder_info": {
    "name": "A. Nakamoto",
    "billing_address": { "line1": "1 Main St", "line2": null, "city": "Austin", "region": "TX", "postal_code": "78701", "country": "US" }
  },
  "created_at": "…",
  "activated_at": null,
  "frozen_at": null,
  "closed_at": null
}
```

`status` is `provisioning`, `active`, `frozen` or `closed`. `network`, `last4`, `exp_month` and `exp_year` are `null` while provisioning. `cardholder_info` is `null` on a card issued in the user's verified name and address.

## Reuse a previous cardholder

`GET /cardholder_info` lists the distinct names and billing addresses the user has put on cards in your grant, most recently used first, for a picker:

```json
{
  "data": [
    {
      "name": "A. Nakamoto",
      "billing_address": { "line1": "…", "line2": null, "city": "…", "region": "…", "postal_code": "…", "country": "…" },
      "last_used_at": "…",
      "card_ids": ["card_…"]
    }
  ],
  "has_more": false,
  "after_cursor": null
}
```

It is derived from non-closed cards, pages with `?limit=` (default 20) and `?after_cursor=`, and never includes the user's verified name and address.

## List and read

`GET /cards` lists the cards on Balances in your grant, active ones by default. `?status=` takes `active`, `provisioning`, `frozen`, `closed` or `all`; anything else is `400 status_invalid`. `?balance_id=` narrows to one Balance. `GET /cards/{id}` reads one.

## Freeze, unfreeze, close

- `POST /cards/{id}/freeze` pauses spend; authorizations decline with `card_frozen` until `POST /cards/{id}/unfreeze`. Both answer `{ "card": Card }` and are idempotent.
- `DELETE /cards/{id}` closes the card for good and answers `204`. The Balance and its funds are untouched, and a new card can be issued on it. Closing a closed card is also `204`.

| Status | Code | Meaning |
| --- | --- | --- |
| 404 | `not_found` | The card is outside your grant. |
| 409 | `card_provisioning` | Not active yet. |
| 409 | `card_closed` | Closed cards cannot be frozen or unfrozen. |

Each change emits `card.frozen`, `card.unfrozen` or `card.closed`.

## Show the card

`POST /cards/{id}/embed_url` mints a short-lived URL that renders the card number, expiry and CVC. It is the only place one is minted; no Balance or card read carries it.

```json
{ "embed_url": "https://final.com/cards/card_…/embed?expires=…&sig=…", "expires_at": "…" }
```

Open it top level in a web view. The URL expires after 15 minutes; mint again after that. The card details never pass through your code, which is what keeps your app out of PCI scope.

| Status | Code | Meaning |
| --- | --- | --- |
| 409 | `card_provisioning` | There is no face to show yet. |
| 409 | `card_closed` | The card is closed. |

## Simulate a purchase

`POST /cards/{id}/test_authorizations` runs the real authorization decision on a test-mode card. See [Test mode](/reference/test-mode).
