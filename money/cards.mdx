## Create a card

`POST /cards` creates a card on a Balance. A new card has the status `provisioning`. The card activates when Final credits a deposit in the Balance tree. A card on a sub-balance activates when Final credits a deposit anywhere in the tree of its root Balance.

```json
{
  "balance_id": "balance_…",
  "cardholder_info": {
    "name": "A. Nakamoto",
    "billing_address": {
      "line1": "1 Main St",
      "line2": null,
      "city": "Austin",
      "region": "TX",
      "postal_code": "78701",
      "country": "US"
    }
  }
}
```

`cardholder_info` contains the name on the card and the billing address that a merchant checks. It applies only to this card.

- `line1`, `city`, `postal_code` and `country` are required.
- `region` is required for US and CA.
- `country` is an ISO 3166-1 alpha-2 code.
- If you send a partial object, Final returns `400 invalid_request`. A partial object is a name without an address, or an address without a name. The `param` field names the field that you did not send.

If you omit `cardholder_info`, Final creates the card with the verified name and address of the user. If Final has no address on file for the user, the call returns `403 user_action_required` with a URL. See [Gates](/money/gates). If you send `cardholder_info`, the user does not need that step.

The response is `{ "card": Card }` with `201`. Each Balance can have one card. If a card already exists, Final returns it with `200`.

| Status | Code | Description |
| --- | --- | --- |
| 400 | `balance_id_required` | The request has no `balance_id`. |
| 403 | `user_action_required`, `verification_pending` | See [Gates](/money/gates). |
| 404 | `not_found` | The Balance is outside your grant. |
| 409 | `balance_closed` | The Balance is closed. |

## Reuse a previous cardholder

`GET /cardholder_info` lists the distinct names and billing addresses that the user put on cards in your grant. The most recently used entry is first. Use the list to show a picker.

```json
{
  "data": [
    {
      "name": "A. Nakamoto",
      "billing_address": { "line1": "…", "line2": null, "city": "…", "region": "…", "postal_code": "…", "country": "…" },
      "last_used_at": "…",
      "card_ids": ["card_…"]
    }
  ],
  "has_more": false,
  "after_cursor": null
}
```

- Final makes the list from cards that are not closed.
- Use `?limit=` (default 20) and `?after_cursor=` to page through the list.
- The list never contains the verified name and address of the user.

## List and read

`GET /cards` lists the cards on Balances in your grant. By default, it lists every card that is not closed.

- `?status=` accepts `provisioning`, `frozen`, `closed` or `all`. `active` gives the same list as the default. For any other value, Final returns `400 status_invalid`.
- `?balance_id=` limits the list to one Balance.
- `GET /cards/{id}` reads one card.

## Freeze, unfreeze, close

- `POST /cards/{id}/freeze` pauses spend on the card. Final declines authorizations with `card_frozen` until you send `POST /cards/{id}/unfreeze`. Both routes return `{ "card": Card }` and are idempotent.
- `DELETE /cards/{id}` closes the card permanently and returns `204`. The Balance and its funds do not change. You can create a new card on the Balance. If the card is already closed, Final also returns `204`.

| Status | Code | Description |
| --- | --- | --- |
| 404 | `not_found` | The card is outside your grant. |
| 409 | `card_provisioning` | The card is not active yet. |
| 409 | `card_closed` | You cannot freeze or unfreeze a closed card. |

For each change, Final sends `card.frozen`, `card.unfrozen` or `card.closed`.

## Show the card

`POST /cards/{id}/embed_url` creates a short-lived URL. The URL shows the card number, expiry and CVC. Final creates this URL only on this route. No read of a Balance or a card returns it.

<EmbedUrlShape />

The full reference is [Embed URL](/reference/objects/embed-url).

Open the URL at the top level of a web view. The URL expires after 15 minutes. After that, create a new one. The card details never pass through your code. This keeps your app out of PCI scope.

| Status | Code | Description |
| --- | --- | --- |
| 409 | `card_provisioning` | The card has no details to show yet. |
| 409 | `card_closed` | The card is closed. |

## Simulate a purchase

`POST /cards/{id}/test_authorizations` runs the real authorization decision on a card in test mode. See [Test mode](/reference/test-mode).
